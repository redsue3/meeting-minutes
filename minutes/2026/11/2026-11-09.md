- 서버 전체를 조회해도 dept, emp, student, course, enroll 테이블이 없었고 스키마만 비어 있어 포워드 엔지니어링이 끝까지 실행되지 않았을 가능성이 제시됐다.
- 교재 정의 그대로는 enroll의 course_no가 기본키이면서 ON UPDATE SET NULL이라 MySQL이 오류 1830으로 거부했다.
- enroll은 대리키 enroll_id를 기본키로 두고 (student_id, course_no)에 UNIQUE를 거는 방식으로 바꿨고, 교재처럼 복합 기본키를 유지하려면 UPDATE 규칙을 CASCADE로 바꿔야 한다고 설명했다.
- 교재의 ON INSERT DEPENDENT는 MySQL에 없는 문법이라 제외했다.
- Workbench 연결 4개 중 Local instance MySQL80과 mydb만 dongseo 작업에 쓸 수 있고, mariaDB는 다른 서버, madang은 권한 부족이라 맞지 않다고 구분했다.
- Workbench에서는 Ctrl+Enter가 아니라 Execute All로 실행해야 USE 문이 빠지지 않는다고 안내했다.

**결정 사항**

- 테이블과 컬럼 이름은 확인 쿼리에 맞춰 영문(dept, emp, student, course, enroll)으로 옮긴다.
- 외래키 삭제·수정 규칙은 교재대로 두고 enroll의 키 구조만 변경한다.
- 재사용을 위해 생성 스크립트와 확인 스크립트를 문서 폴더에 저장한다.

**진행한 작업**

- dongseo에 테이블 5개와 외래키 3개를 만들고 DELETE/UPDATE 규칙이 교재 표와 일치함을 확인했다.
- 사용자가 붙여준 확인 쿼리를 수정 없이 실행해 오류 없이 결과가 나오는 것을 검증했다.
- 생성 스크립트(01_create_tables.sql)와 확인 스크립트(02_check.sql)를 문서 폴더에 저장하고 처음부터 다시 실행해 정상 동작을 확인했다.
- MySQL 서비스가 자동 시작으로 설정돼 있음을 확인했다.
- Workbench와 명령줄 접속 방법, 서버 접속 정보와 파일 위치를 정리해 안내했다.
- cmd에서 확인 쿼리 실행 과정을 결과와 함께 보여주는 명령을 제공했다.

**후속 작업**

- [ ] 사용자: 과제 제출을 위해 Workbench의 Reverse Engineer로 dongseo 스키마를 불러온 뒤 Forward Engineer를 실행하고 화면을 캡처한다.
- [ ] 사용자: 테이블이 사라졌다면 생성 스크립트를 먼저 실행한 뒤 확인 스크립트를 실행한다.

**이슈·리스크**

- 교재 정의의 복합 기본키 구조는 MySQL에서 오류가 나므로 enroll이 교재와 다른 구조이고, Workbench 모델에서 enroll을 그릴 때도 같은 오류가 날 수 있다.
- 생성 스크립트는 기존 테이블을 지우고 다시 만들기 때문에 데이터를 넣은 뒤 실행하면 데이터가 삭제된다.
- 대화 중 일부 명령에 비밀번호가 그대로 쓰였고 cmd 명령에도 비밀번호가 포함되어 있어 노출 위험이 있다.
